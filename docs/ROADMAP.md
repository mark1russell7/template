# Roadmap

This file is the plan of the template. The Status page of the site reads it, and the tracker of the strategist mirrors it.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| T1 | Gates fail closed | done, 2026-10-30 | The OK steps of the shared CI fail on a skip that `ALLOW_SKIP` does not name and on an empty `needs` (#85). conventions 0.5.0 adds `typed-files` and `tests-required` (#86). conventions 0.6.0 adds `roadmap-parses` (#87). |
| T2 | A site with no roadmap fails | done, 2026-10-30 | conventions 0.7.0 (#88): `roadmap-parses` fails on a call of `reusable-pages.yml` with no `roadmap`. Before, the rule skipped it, and the Status page of the site showed no item of the plan. |
| T3 | Each repository on the newest conventions | in progress | Each repository of the fleet takes the newest `@mark1russell7/conventions` and passes `check:conventions` on `main`. The strategist checks each one on `main`. |
| T4 | The runner budget as a rule | done, 2026-11-01 | conventions 0.8.0 adds the rule `runner-budget` (#92). Each matrix has a `max-parallel` of 3 or less, and each workflow has a concurrency group. The minute of each schedule comes from a hash of the repository and the file. Before, each repository copied the weekly scan of `security.yml` at `23 5 * * 1`, so all scans started at the same minute. conventions 0.8.1 (#95) accepts a schedule that starts more than once in each hour, at equal steps from the minute (`18,48`). Next, each repository takes 0.8.1 (T3). |
| T5 | The site of the template | done, 2026-11-02 | `pages.yml` deploys the site of the template: the home page, the Releases page and the Status page. It uses `reusable-pages.yml` of its own commit. Since 11-02, the home page is the Vite build of `packages/site`. It shows the files of each preset of the CLI and which steps of a shared workflow run. The site check examines it on each pull request. |
| T6 | The check CI OK is necessary on main | waiting on Mark | The ruleset of `main` needs the summary checks, for example CI OK. Mark starts `scripts/workflows/ruleset-ci-ok.ts --only-summary --apply`, because a ruleset is a setting of the repository. With `--only-summary` (#94), the script also removes the per-job checks that CI OK covers. Then a repository can join or split its CI jobs. |
| T7 | A docs commit moves no pin | done, 2026-10-30 | The release train moves the pins of a repository only when the surface of a pin changed (release-train #42). The surface is the file of a shared workflow, its `sparse-checkout` paths, or the folder of an action. Before, a docs commit of the template pushed a sync pull request to approximately 20 repositories. Their CI filled 39 of the 40 runners. |
| T8 | `conventions fix` for the mechanical breaks | done (11-01) | Since 10-30, the release train pull requests to conventions 0.7.0 have been blocked in 7 repositories. conventions 0.8.2 adds `conventions fix`: a break can have exact edits, and the fix writes them until none applies. It fixes the minute of a schedule, `max-parallel`, a concurrency group, `passWithNoTests` in a package with tests, and the config files of a `tsconfig.test.json`. On the main branches of 7 blocked repositories, it fixed each break of `runner-budget` and `tests-required` (vex 4 to 0, client 5 to 0, crawler 18 to 9, render 19 to 8). Each break that stays is a JavaScript source of `typed-scripts`, which a person converts. Since 11-01, the train starts the fix of the new version in each update pull request (release-train #47). It installs the packages first, because `typed-files` reads the tsconfig files with the TypeScript of the repository. On a fresh clone of Logger, the fix changed 1 line and no break stayed. |
| T9 | Each gate feeds a summary that the ruleset needs | in progress | On 11-02, 16 workflows in 8 public repositories had `paths` on `on.pull_request`. Such a workflow does not start on each pull request, so the ruleset cannot ask for its check, and `gh pr merge --auto` can merge before it ends. #104 adds the actions `changes` and `gate-summary`, and `actions-test.yml` uses them. conventions 0.11.0 adds the rule `gate-trigger`, and its fix converts each of the 15 other workflows. Next, the train takes 0.11.0 into each repository. Then `ruleset-ci-ok.ts --only-summary --apply` adds each new summary to the ruleset. conventions 0.12.0: the rule `release-files` does not trust a shallow checkout that ends inside the change (on coeval #183 it hid the commit of the train), and the CI deepens such a checkout to the merge base. |
| T10 | Each public repository has a site | in progress | conventions 0.17.0 adds the rule `pages-site`. In a GitHub Actions run of a public repository, a workflow must use `reusable-pages.yml` without `deploy: false`. On 2026-11-02, seven public repositories had no site: typeset, algebra, headroom, release-train, optional, ste-lint and lag-hud. Next, each of them adds `pages.yml` and sets the Pages source to "GitHub Actions". |
| T11 | Each shipped change gets to npm | in progress | On 2026-11-02, rigor #20 and #18 set the same version. The release of #20 published it. The merge of #18 changed no version, so `release.yml` did not start, and #18 did not get to npm. Nothing failed. conventions 0.18.0 adds the rule `unreleased-change`. A pull request that sets a version that npm has fails. With the option `versionEachChange`, a change of the shipped files with a version that npm has also fails, also on the push to `main`. Next, the train takes 0.18.0 into each repository, and rigor sets `versionEachChange`. |
| T12 | One run for each commit | in progress | A commit on a branch with an open pull request starts `push` and `pull_request`, so CI runs two times. conventions 0.27.0 adds the rule `push-main-only` with a fix, and the `ci.yml` of the template obeys it. The fix changes 36 workflows in 36 public repositories, and one more needs a person. Next, the train takes 0.27.0 into each repository. |
